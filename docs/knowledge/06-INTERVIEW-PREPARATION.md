# Interview preparation

Use answers as explanations to understand, not scripts to recite. Questions 1–23 focus on AI/RAG. Source detail is in [AI explained](04-AI-AND-RAG-EXPLAINED.md); other answers link to the relevant chapter. Examples of personal contribution must be adapted honestly to your work, including AI-assisted development.

## AI foundations and implementation

### 1. What is RAG, and why does AskAnon need it?

**Say:** “RAG retrieves relevant course passages and gives them to Gemini before it answers. That makes the answer depend on the teacher's PDFs rather than only general model knowledge.”

### 2. Is the project just an LLM API call?

**Say:** “Generation uses a hosted API, but I also implemented the surrounding document ingestion, vectors, access filtering, retrieval, citations and failure handling.”

### 3. What are AI, an LLM and Gemini?

**Say:** “AI is the broad field. An LLM generates language based on learned patterns; Gemini is the hosted model family we call.”

### 4. What is an embedding?

**Say:** “It is a numerical representation of text used to compare meaning. We request 768 numbers for each passage and question.”

### 5. What are tokens, prompts and a context window?

**Say:** “Tokens are model-specific text units. A prompt is the input instructions and data. The context window limits what the model can consider in a request.”

### 6. Why RAG instead of fine-tuning?

**Say:** “We need changing course knowledge, not a new model behaviour. RAG can index a new PDF and retrieve it without retraining.”

### 7. Explain a PDF upload all the way to an answer.

**Say:** “The teacher uploads to Cloudinary; the backend extracts page text, chunks and embeds it, then stores vectors in PostgreSQL. A student's question is authorized, embedded and compared with those vectors. Selected excerpts go to Gemini, and the UI shows the answer and sources.”

### 8. Why chunk documents? Why this chunk size?

**Say:** “We search smaller passages instead of sending an entire PDF every time. The current function uses about 1,200 characters with page metadata.”

### 9. How do scanned PDFs work?

**Say:** “Native text is extracted first. Unreadable pages are rendered and sent for bounded Gemini transcription.”

### 10. Where are vectors stored? Is it IndexedDB?

**Say:** “They are stored in PostgreSQL using pgvector, alongside chunk text and metadata. Browser IndexedDB is not used as our vector store.”

**Go deeper:** `MaterialChunk.embedding` is `vector(768)`. Redis caches results; Cloudinary stores originals. Storing vectors and configuring a fast approximate vector index are different claims. No HNSW/IVFFlat definition is checked in.

### 11. What does cosine similarity measure?

**Say:** “It measures vector direction similarity, which helps find text with related meaning even when words differ.”

### 12. How many passages are retrieved? How do you filter them?

**Say:** “The active flow takes 8 seeds for one PDF or 12 for a course, keeps scores at least 0.45 and adds neighbors with a bounded context size.”

**Go deeper:** Expansion caps at 14/18 chunks. Those values come from the active caller, not the smaller search-helper defaults. Threshold calibration needs evaluation; it can reject useful matches or retain weak ones.

### 13. How do you prevent cross-course leakage?

**Say:** “Backend ownership/enrollment checks happen before RAG, and the vector query is restricted to the authorized material or course.”

**Go deeper:** Filtering only the generated answer would be too late. Cache access must also remain behind authorization. Trace [material routes](../../backend/src/routes/materialRoutes.js) and [access checks](../../backend/src/middleware/accessMiddleware.js).

### 14. What if no relevant passage exists?

**Say:** “The system returns an insufficient-evidence message instead of generating a guessed course answer.”

**Go deeper:** An empty filtered result skips generation. Weak but retained passages can still mislead the model; the threshold is imperfect. Prompt instructions require admission of missing information but are not a mathematical guarantee.

### 15. How do sources work? Do they eliminate hallucinations?

**Say:** “Sources and evidence identify the retrieved materials/pages, helping the student check the answer. They do not eliminate hallucinations.”

**Go deeper:** Source metadata is server-assembled; inline claim citations are generated by Gemini. There is no independent claim-by-claim entailment verifier. Distinguish retrieving a real page from proving a generated claim follows from it.

### 16. How does conversation history affect retrieval?

**Say:** “A bounded set of recent turns helps resolve follow-ups, but the documents remain the evidence.”

### 17. Does summary mode read the whole course?

**Say:** “No. It samples first, middle and last chunks from a bounded set of documents and reports coverage.”

### 18. How does moderation differ from RAG?

**Say:** “Moderation classifies a submission against lecture context; it doesn't retrieve PDF evidence. RAG retrieves course passages to answer a question.”

**Go deeper:** Local checks and Gemini classification occur before written publication. Provider failure blocks unchecked text. Instructor broadcasts and attachment-only submissions have different paths. See [contentModerator](../../backend/src/utils/contentModerator.js) and question creation.

### 19. How does duplicate detection work?

**Say:** “It first checks normalized exact text, then compares a new question's embedding with cached embeddings of recent active questions.”

**Go deeper:** Candidate count is bounded at 25; semantics can miss candidates without warm vectors. The threshold defaults to 0.82 with an environment override, unlike document search's 0.45. It suggests upvoting rather than guaranteeing no duplicates. Evidence: [embeddingService](../../backend/src/utils/embeddingService.js).

### 20. What if Gemini is down or quota is exhausted?

**Say:** “Optional duplicate hints can disappear, but moderation must succeed before written publication. Vault requests return useful errors; selected generation calls can try one bounded fallback.”

**Go deeper:** Moderation has a four-second primary attempt and ten-second overall budget; vault fallback handles overload within its request deadline. 429 quota errors are not endlessly retried. Same-provider fallback does not survive every provider outage. Recap and embedding calls do not share every fallback policy.

### 21. What if indexing fails halfway or a PDF changes?

**Say:** “Replacement chunks are committed only after all embeddings succeed. A failed reindex should not erase a previous complete index.”

### 22. What are hybrid search and reranking? Did you implement them?

**Say:** “Hybrid search combines keyword and semantic matches; reranking scores retrieved candidates again. AskAnon currently implements neither.”

**Go deeper:** Exact duplicate matching is not hybrid PDF retrieval. Neighbor expansion is not reranking. Introduce these only if evaluation exposes missed exact terms or poor ranking, rather than adding infrastructure for terminology.

### 23. How would you evaluate RAG, reduce cost and improve safety?

**Say:** “I would prepare questions with known evidence, test retrieval separately from answer quality, track unsupported claims and latency, and use caching and bounded requests.”

**Go deeper:** Include unsupported questions, paraphrases, scans and malicious document instructions. Cache hits and quotas reduce calls; uploaded OCR/embedding volume still matters. Prompts treat documents as untrusted, but prompt-injection protection is incomplete. A formal quality benchmark is a next step, not an existing achievement.

## Application engineering and design

### 24. Explain the architecture without listing libraries.

**Say:** “The browser sends authenticated requests to one backend. PostgreSQL stores durable classroom state; sockets notify the relevant participants. Storage, authentication and AI are external services.”

### 25. Where does the application start? How would you navigate its code?

**Say:** “Frontend main creates providers, App defines routes, pages coordinate state and components render parts. Backend app mounts routes; middleware checks requests; controllers use Prisma and service-like utilities.”

### 26. Why React/Vite rather than Next.js?

**Say:** “A client-rendered interactive classroom with a separate backend fits React/Vite without adding server-rendering architecture.”

### 27. Why Socket.io instead of polling or plain WebSockets?

**Say:** “Classroom updates should arrive when they happen. Socket.io provides rooms, acknowledgements and reconnection support around real-time connections.”

### 28. What happens after a disconnect?

**Say:** “The client rejoins and fetches persisted room state, including pause and poll information. It doesn't rely on receiving every missed event.”

**Go deeper:** Notifications are not the durable record. An event replay log is not implemented. Compare state synchronization with exactly-once message delivery; do not claim the latter.

### 29. Authentication versus authorization?

**Say:** “Clerk proves identity. Our backend checks whether that identity owns the session or is enrolled in the course.”

### 30. What does anonymous mean here?

**Say:** “Question cards don't show names, and the current question table has no author foreign key. Account-related activities such as votes and enrollment still have identity associations.”

**Go deeper:** Don't promise an abuse-author lookup that the schema cannot support, or total privacy that ignores external services/logs. See the [security explanation](05-DECISIONS-AND-RELIABILITY.md).

### 31. Why PostgreSQL and Prisma?

**Say:** “Courses, sessions, votes and enrollments have clear relations and consistency requirements. PostgreSQL constraints and transactions fit them; Prisma simplifies most CRUD.”

### 32. How do you prevent double votes and racing pins?

**Say:** “Votes use a unique user/question pair and a transaction containing the insert and counter increment. Pin changes use a Serializable transaction.”

**Go deeper:** UI disabling is only feedback. Retry `P2034` serialization conflicts, handle duplicate-key errors and let rollback prevent partial counts. The question pin invariant isn't a dedicated partial unique index in this schema.

### 33. Why Redis if you already have PostgreSQL?

**Say:** “Redis avoids repeated reads and supports expiring counters. PostgreSQL remains authoritative.”

### 34. How do you avoid stale UI and duplicate cards?

**Say:** “The backend invalidates affected caches and publishes changes; clients reconcile records by ID and refresh snapshots when needed.”

### 35. Why can pinning be slow if it doesn't use AI?

**Say:** “It still waits for authorization, remote database writes, cache invalidation and notifications. I would measure those stages rather than assume every delay is Gemini.”

### 36. Why background jobs for deletion and indexing?

**Say:** “They can take longer than an ordinary interaction, so the UI acknowledges the request and shows state while work continues.”

**Go deeper:** Deletion has persisted jobs/leases; indexing has a process-local registry and retryable status. They are not equally durable queues. `202` means accepted, not completed. See [feature flows](03-HOW-FEATURES-WORK.md).

### 37. How do database and Cloudinary deletion stay consistent?

**Say:** “Database relationships are pruned transactionally, and external asset deletion is queued with reference checks.”

**Go deeper:** A database cannot roll back a Cloudinary request. Shared diagram assets must survive if still referenced by the vault. Durable cleanup reconciles the separate systems.

### 38. What would be needed to run several backends?

**Say:** “We need shared socket fan-out, consistent room/access state, coordinated workers and review of caching—not just another instance.”

### 39. What do your tests prove?

**Say:** “They cover selected authorization, lifecycle, concurrency and AI failure behaviours, plus build/lint checks. Real provider quality and deployment still require separate checks.”

### 40. What is the biggest practical limitation?

**Say:** “The demo relies on free hosting and external AI quotas, and its architecture is currently single-backend. I would first measure reliability and retrieval quality before adding infrastructure.”

## Product, contribution and demo

### 41. Why build this rather than another chat app?

**Say:** “A lecture has specific needs: low-friction anonymous questions, voting, teacher control and access to the materials afterward. The vault connects live doubts with later study.”

### 42. Why no university administrator or teacher approval?

**Say:** “The demo keeps entry simple: people choose a role once and teachers own only their own resources.”

### 43. What did you personally contribute, and did you use AI tools?

**Suggested structure:** “I worked on [specific behaviour you can demonstrate]. I used AI assistance for [actual tasks], reviewed [actual decisions] and verified [actual checks]. I can walk through [specific code path].”

**Go deeper:** Don't claim you manually authored every line or invented the model. Distinguish selecting requirements, integrating services, understanding the code and testing it. Prepare a concrete example rather than a generic claim.

### 44. What was a difficult bug or decision?

**Suggested structure:** Describe a real problem → root cause → change → evidence → remaining limitation. Examples present in project history include duplicate-email onboarding recovery, remote interaction latency and intermittent moderation-provider failures.

**Go deeper:** Verify the relevant change and tests before using it as your story. Avoid fabricated performance percentages, invented user feedback or claiming that a fallback removes all outages.

### 45. How would you demonstrate AskAnon in five minutes?

1. Explain the problem and open a prepared teacher/student pair of accounts.
2. Show a lecture code and student join; point out corresponding vault access.
3. Submit an academic question, vote from another participant and pin/write an answer.
4. Show a poll or shared diagram briefly rather than clicking every control.
5. Ask a prepared PDF question, open the source/evidence and explain the RAG pipeline.
6. Show ended-session recap and state one limitation/next improvement.

Prepare the PDF index before the demo; waiting for ingestion isn't useful storytelling. If the provider is down, show retrieved evidence and explain the failure policy honestly. Keep a recorded walkthrough as a backup, labeled as recorded.

Without notes, draw the architecture, locate the vote constraint and explain one source citation. Then answer: “What changes if Redis fails?” and “What is the difference between missing evidence and a failed generation call?” If you cannot trace the implementation, read its chapter and open the source before adding more interview terminology.
